# GameProfileV2 reference

`GameProfileV2` is a versioned, declarative contract. The machine-readable schema is authoritative once frozen; this page explains its stable intent.

The authoritative schema is `schemas/game-profile-v2.schema.json`; profile documents live at `profiles/games/<slug>/profile.json`.

## Required sections

- **identity:** profile ID, schema version, display name, game/publisher references, original-content provenance.
- **detection:** stores, manifests/registry/common paths, processes, executable hashes/build rules, manual fallback.
- **safety:** allowed single-player modes, online/protected/anti-cheat signals, ambiguity policy, capture/overlay refusal.
- **capture:** target window/process, content/UI exclusions, display modes, fallback.
- **capabilities:** level, evidence, requirements, build scope, certification, and explicit fallback for each capability.
- **identity evidence:** approved telemetry/OCR/UI/vision/manual sources, fusion thresholds, track timeout.
- **content:** world lore, characters, biographies, personality/style, prompts, spoiler tiers, background-NPC rules, provenance.
- **defaults:** provider-neutral model/voice and performance recommendations.
- **external integration:** built-in capture/selection strategy IDs and tested build/display scope; no mod or executable component.
- **diagnostics/troubleshooting:** health probes, typed failure reasons, user guidance.

## Validation invariants

- Stable unique IDs; known schema version; no unknown executable fields.
- All paths/regions/ranges bounded and normalized.
- Every advertised capability has evidence, build scope, and fallback.
- Risk-gated profiles refuse protected, online, anti-cheat, or ambiguous modes.
- Content carries provenance/license metadata; profile data contains no secrets, binary pickles, copied media, or Python.
- Named characters and background encounter identities cannot share mutable memory.
- Replay fixtures are deterministic and separate from live certification.

Every individual capability carries one evidence status: `unsupported`, `experimental`, `replay_verified`, or `live_certified`. A profile-level authored state never promotes its capabilities automatically.

## Compatibility

Schema migrations are explicit and tested. Unknown major versions are rejected; unsupported optional capability fields degrade only where the schema says they are optional. Legacy adapter-shaped fields, if retained temporarily for migration compatibility, are dormant and do not authorize or require executable integration.

See [authoring guide](../guides/game-profiles.md). Do not copy this prose into a hand-written implementation schema; use the repository schema generated by the profile subsystem.
